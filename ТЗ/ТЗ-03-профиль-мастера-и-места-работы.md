# ТЗ-03 — Профиль мастера и места работы

## 1. Назначение

Реализовать две самостоятельные бизнес-сущности:

- **E-02 — Profile / Профиль мастера**
- **E-03 — Workplace / Место работы**

ТЗ-03 дополняет уже существующую архитектуру Book и не создаёт новый корень приложения, новую ветку навигации или отдельную систему UI/CSS.

---

## 2. Архитектура

```text
Настройки
└── Профиль
    │
    ├── E-02 Profile
    │   ├── Accordion: Личные данные
    │   └── Accordion: Профессиональные данные
    │
    └── Папка: Места работы
        │
        └── E-03 Workplace
            ├── Workplace 1
            ├── Workplace 2
            └── Workplace N
```

**E-02 Profile** — одна сущность мастера.

**E-03 Workplace** — отдельная сущность места работы.

Один Profile может иметь несколько Workplace.

---

## 3. Важное разграничение

`Личные данные` и `Профессиональные данные` не являются сущностями.

Это два Accordion-раздела внутри E-02 Profile, через которые создаются и редактируются данные профиля.

`Места работы` — отдельная папка/раздел, содержащая сущности E-03 Workplace.

Workplace не является подразделом данных Profile.

---

## 4. Profile — данные

### Личные данные — Accordion

- **Имя \*** — text input, placeholder «Ваше имя».
- **Фамилия** — text input, placeholder «Ваша фамилия».
- **Телефон \*** — общий phone input.
- **О себе** — короткий text/textarea.
- **Фото** — загрузка фотографии Profile.

### Профессиональные данные — Accordion

**Профессия** — выпадающий список:

- Парикмахер
- Колорист
- Барбер
- Визажист
- Стилист
- Мастер маникюра
- Мастер педикюра
- Бровист
- Лэшмейкер
- Косметолог
- Массажист
- Мастер по наращиванию волос
- Мастер перманентного макияжа
- Другая

При выборе «Другая» пользователь может добавить собственное значение, после чего оно становится доступным в списке.

**Опыт работы** — выпадающий список:

- Без опыта
- До 1 года
- 1–3 года
- 3–5 лет
- 5–10 лет
- 10–15 лет
- 15–20 лет
- Более 20 лет

**О профессии** — text/textarea.

---

## 5. Сохранение Profile

Кнопка **Сохранить** сохраняет данные Profile.

Личные и профессиональные данные принадлежат одной сущности E-02.

---

## 6. Profile Card

После заполнения Profile отображается карточка профиля мастера.

До заполнения карточка существует как пустое состояние.

Используется **тот же общий Entity Card**, который применяется в Client.

Не создавать отдельный CSS/UI-паттерн для Profile Card.

Визуальная модель карточки — единая для сущностей Book и может восприниматься как банковская карта/визитка.

Карточка Profile содержит:

- фотографию как background/заливку, если фото загружено;
- телефон;
- имя и фамилию;
- профессию в правой нижней части.

Телефон визуально оформляется как основной номер карточки.

Если фото отсутствует, не создавать искусственное изображение или отдельную avatar-модель.

---

## 7. Места работы

Раздел **Места работы** является контейнером сущностей E-03.

В заголовке списка:

```text
Места работы                                      [+]
```

Кнопка `[ + ]` находится справа.

Используется существующий общий UI-компонент `[ + ]`.

Не создавать новый вариант кнопки.

До создания первой сущности список пуст.

---

## 8. Создание Workplace

Нажатие `[ + ]` открывает существующее общее модальное окно Book.

Заголовок модального окна:

**Новое место работы**

Справа сверху:

`[ X ]`

Нажатие `[ X ]` закрывает окно без создания новой сущности.

---

## 9. Данные Workplace

### Фото

Возможность загрузить фотографию рабочего места/салона.

Если фото загружено, оно используется как background/заливка Workplace Card.

### Название

Text input.

### Город

Searchable Select.

При вводе первой буквы/первых символов список автоматически фильтрует города для ускорения заполнения.

### Адрес

Text input.

### Рабочий телефон

Общий phone input.

### Валюта

Общий dropdown с доступными валютами.

### График работы

В одну строку:

```text
с [ время ] до [ время ]
```

Используется общий Time Picker/Input.

### Рабочие ссылки

Использовать уже существующий механизм рабочих ссылок из Client.

Не создавать второй механизм ссылок.

### О рабочем пространстве

Text/textarea.

---

## 10. Сохранение Workplace

Кнопка **Сохранить**:

1. создаёт сущность E-03 Workplace;
2. связывает её с текущим E-02 Profile;
3. закрывает модальное окно;
4. добавляет Workplace в список.

---

## 11. Workplace List

После создания Workplace в списке отображаются:

- название;
- часы работы `с ... до ...`.

Название является интерактивным и открывает Workplace Card.

**Счётчик записей в рамках ТЗ-03 не реализуется и не упоминается в UI.**

---

## 12. Workplace Card

Workplace использует **тот же общий Entity Card**, что Client и Profile.

Не создавать отдельную Workplace Card CSS/UI-систему.

Если фото существует — оно используется как background/заливка.

### Верхняя часть

- название места работы — жирный шрифт, не крупный заголовок;
- часы работы — обычный шрифт;
- рабочий телефон — обычный шрифт, только если указан;
- справа сверху — данные, предусмотренные текущей моделью карточки, без добавления счётчика записей.

### Нижняя часть

Отображаются данные связанного E-02 Profile:

- телефон мастера — основной, жирный;
- имя и фамилия — жирный;
- профессия — справа внизу, обычный шрифт.

Workplace Card является визиткой мастера **в конкретном месте работы**.

Profile Card является визиткой мастера **как самостоятельного профиля**.

При этом обе карточки используют одну и ту же визуальную модель Entity Card.

---

## 13. Связь Profile и Workplace

Основные данные мастера не дублируются в Workplace как независимые данные.

Workplace связан с E-02 Profile и получает для отображения:

- имя;
- фамилию;
- телефон мастера;
- профессию.

Изменение этих данных в Profile должно отражаться в соответствующем Workplace Card без создания второй независимой сущности мастера.

---

## 14. Общий UI/Core/CSS

Все новые элементы используют существующую общую систему Book.

Обязательно использовать существующие общие компоненты:

- Entity Card;
- `[ + ]`;
- `[ EX ]`, если Excel потребуется в будущем;
- сортировку, если она появится в данном списке;
- Accordion;
- Modal;
- `[ X ]`;
- Input;
- Phone Input;
- Select;
- Searchable Select;
- Time Input/Picker;
- механизм рабочих ссылок;
- кнопку Сохранить.

Не создавать локальные копии этих компонентов.

Если общий компонент сейчас визуально реализован неправильно, исправление выполняется в общем компоненте, чтобы изменение распространялось на все места его использования.

---

## 15. Общие управляющие элементы

### `[ + ]`

Всегда использовать единый компонент.

В списке Workplace — справа.

### `[ EX ]`

В ТЗ-03 Excel не добавляется.

Если Excel потребуется в дальнейшем, используется существующий общий компонент Excel с единым положением и размером.

### Сортировка

Отдельная функциональность сортировки ТЗ-03 не добавляется.

Если сортировка используется, она должна быть общим компонентом и располагаться справа, с тем же размером и визуальной точкой расположения, что и в остальных сущностях.

---

## 16. Фото и Entity Card

В Book используется единое понимание фотографии карточки:

```text
фото сущности → background / заливка Entity Card
```

В рамках ТЗ-03:

- Profile → Profile Card;
- Workplace → Workplace Card.

Client получает эту же возможность через отдельную правку к ТЗ-02.

---

## 17. Мобильная реализация

ТЗ-03 реализуется в существующей смартфонной архитектуре Book.

Не допускается:

- горизонтальный скролл страницы;
- отдельная desktop-архитектура;
- отдельная мобильная копия UI;
- локальная копия CSS.

Modal, Accordion, Select, Time Picker, поля и карточки должны корректно работать на смартфонной ширине.

---

## 18. Ограничения

ТЗ-03 не создаёт:

- отдельную сущность Master;
- отдельную сущность Personal Data;
- отдельную сущность Professional Data;
- отдельную сущность Profile Card;
- отдельную сущность Workplace Card;
- второй Entity Card;
- локальный CSS;
- локальный UI;
- второй механизм рабочих ссылок;
- счётчик записей Workplace;
- новую ветку нижней навигации.

---

## 19. Связь с предыдущими ТЗ

ТЗ-03 дополняет:

- ТЗ-01 — архитектурный фундамент;
- ТЗ-01-ПРАВКИ — единый архитектурный/UI-фундамент;
- ТЗ-02 — сущность Client.

ТЗ-03 не отменяет и не переписывает ранее исполненные ТЗ.

При необходимости изменения общего UI исправляется общий компонент, а не создаётся его локальная копия.

---

## 20. Критерии готовности

### E-02 Profile

Сущность считается реализованной после проверки:

1. Profile существует как одна сущность мастера;
2. внутри Profile есть Accordion «Личные данные»;
3. внутри Profile есть Accordion «Профессиональные данные»;
4. Personal Data и Professional Data не зарегистрированы как отдельные сущности;
5. Profile поддерживает фото;
6. Profile Card использует общий Entity Card;
7. фото отображается как background/заливка;
8. данные Profile сохраняются;
9. профессия и опыт работы выбираются из предусмотренных списков;
10. пользовательская профессия через «Другая» сохраняется и доступна повторно.

### E-03 Workplace

Сущность считается реализованной после проверки:

1. Workplace является самостоятельной сущностью;
2. один Profile может иметь несколько Workplace;
3. Workplace создаётся через общий `[ + ]`;
4. `[ + ]` расположен справа;
5. создание происходит в общем Modal;
6. Workplace поддерживает фото;
7. фото отображается как background/заливка;
8. заполненные данные отображаются в Workplace List;
9. название открывает Workplace Card;
10. Workplace Card использует тот же Entity Card;
11. данные мастера берутся из связанного Profile;
12. рабочие ссылки используют существующий механизм Client;
13. счётчик записей отсутствует.
