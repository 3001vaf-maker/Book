# ТЗ-05 — Кошелёк

## 1. Назначение

Добавить и привести к существующей архитектуре Book сущность **E-06 — Wallet / Кошелёк**.

На текущем этапе реализуются только контейнер сущности, список кошельков, создание кошелька, фото, название, карточка кошелька, текущий функционал «Работа с кошельком» для фотографии и навигация.

Бизнес-логика кошелька сейчас не реализуется. Она будет добавлена позднее отдельным ТЗ/правкой E-06 после готовности необходимых связанных сущностей.

## 2. Существующая реализация и расположение

В приложении уже существует ветка:

```text
Настройки → Кошельки
```

Новую параллельную ветку создавать нельзя.

Перед изменениями исполнитель обязан проверить фактическую реализацию этой ветки, включая HTML/JS/TS, маршруты, состояния, навигацию и связанные UI/CSS-компоненты.

Существующую реализацию необходимо использовать как основу и скорректировать в соответствии с настоящим ТЗ. Переписывать её с нуля нельзя.

Существующий раздел **«Кошельки»** необходимо переименовать в **«Кошелёк»**.

После изменения:

```text
Настройки
└── Кошелёк
```

Параллельной ветки `Кошелёк` создавать нельзя.

Необходимо проверить и скорректировать связанный JS/TS-код, маршруты, идентификаторы, обработчики, состояния и навигацию, чтобы переименование работало корректно. Не выполнять механическую замену текста там, где это нарушает существующую архитектуру.

Существующая рабочая функциональность и данные не должны быть потеряны.

## 3. Архитектура сущности

**E-06 — Wallet / Кошелёк** — одна сущность.

Раздел «Кошелёк» является контейнером экземпляров E-06.

```text
Кошелёк
├── Наличные
├── Безналичные
└── пользовательские кошельки
```

`Наличные`, `Безналичные` и пользовательские кошельки являются экземплярами одной сущности E-06. Отдельные сущности для конкретных кошельков создавать нельзя.

## 4. Список кошельков

Путь:

**Настройки → Кошелёк**

Заголовок:

**Кошелёк** `[ + ]`

В списке изначально существуют два системных кошелька:

- **Наличные**
- **Безналичные**

Пользовательские кошельки создаются через `[ + ]`.

На текущем этапе финансовые показатели в списке не реализуются.

## 5. Создание нового кошелька

При нажатии `[ + ]` открывается существующее стандартное модальное окно Book.

Новая система модальных окон не создаётся.

Содержание:

```text
Новый кошелёк                         [ X ]

[ Добавить фото ]

Название кошелька
[________________________]

[ Сохранить ]
```

### Фото

Фото необязательно. Пользователь может добавить фотографию, которая используется для визуала карточки кошелька.

### Название кошелька

Название обязательно. Без названия кошелёк не создаётся.

### Сохранить

После сохранения создаётся новый экземпляр E-06 и появляется в списке кошельков.

### X

При нажатии `[ X ]` модальное окно закрывается без создания кошелька.

## 6. Открытие существующего кошелька

При нажатии на кошелёк в списке открывается его карточка.

На экране присутствуют:

```text
[ карточка кошелька ]

[ Работа с кошельком ]
[ Назад ]
```

## 7. Карточка кошелька

Используется существующий общий **Entity Card Book**.

Новый локальный компонент карточки создавать нельзя.

Карточка визуально соответствует общей системе Book и имеет форму банковской карты.

### Фото

Если фото установлено, оно используется как визуальная поверхность карточки.

Если фото отсутствует, используется существующее стандартное оформление Entity Card.

### Название

Название кошелька располагается **в левом верхнем углу карточки**.

### Остальная информация

На текущем этапе на карточке не отображаются сумма, баланс, даты, операции, история, периоды или другие финансовые показатели.

## 8. Работа с кошельком

На экране существующего кошелька присутствует кнопка:

**[ Работа с кошельком ]**

На текущем этапе единственный реализованный функционал — **добавление/изменение фотографии кошелька**.

Это применяется к Наличным, Безналичным и пользовательским кошелькам.

Другие функции сейчас не создавать.

Будущая функциональность будет добавлена отдельным ТЗ/правкой E-06.

## 9. Навигация

Используется существующее общее правило Book: **«Назад» всегда возвращает на один шаг назад.**

```text
Настройки
   ↓
Кошелёк
   ↓
Наличные
```

Поэтому:

- `Кошелёк → Назад → Настройки`;
- `Наличные → Назад → Кошелёк`;
- `Безналичные → Назад → Кошелёк`.

Для пользовательского кошелька действует то же правило.

`[ X ]` в модальном окне только закрывает модальное окно и возвращает пользователя на текущий экран.

Новое правило навигации не создавать.

## 10. Граница текущего ТЗ

В ТЗ-05 не проектируется и не реализуется финансовая бизнес-логика кошелька.

Не реализуются:

- поступления;
- расходы;
- баланс;
- история оплат;
- даты оплат;
- выбор периода;
- финансовые операции;
- связь оплаты с процедурой;
- связь с Журналом;
- финансовые отчёты;
- расчёт финансовых показателей.

Эта логика будет добавлена позже отдельным ТЗ/правкой E-06 и будет общей для всех экземпляров кошелька.

## 11. Критерии приёмки

- существующая ветка `Настройки → Кошельки` используется как основа;
- существующий раздел переименован в `Кошелёк` без создания параллельной ветки;
- E-06 определена как единая сущность Wallet / Кошелёк;
- Наличные, Безналичные и пользовательские кошельки являются экземплярами E-06;
- в списке изначально присутствуют Наличные и Безналичные;
- через `[ + ]` создаётся пользовательский кошелёк;
- фото необязательно;
- название обязательно;
- новый кошелёк появляется в списке после сохранения;
- существующий кошелёк открывает его карточку;
- используется существующий Entity Card;
- название находится в левом верхнем углу карточки;
- `Работа с кошельком` на текущем этапе позволяет только добавить/изменить фото;
- `Назад` возвращает на один шаг назад;
- существующие Core/UI/CSS, общие компоненты, данные и рабочая функциональность не заменяются и не теряются;
- новая система модальных окон, навигации или карточек не создаётся;
- финансовая бизнес-логика не реализуется.
