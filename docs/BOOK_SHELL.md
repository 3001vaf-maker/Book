# Book Shell — буквенная схема интерфейса

Этот документ фиксирует общий стандарт Book shell для всех новых и постепенно перерабатываемых разделов Book. Это не клиентский shell: клиентская часть была первой, где стандарт применён полностью.

## Схема

```text
┌─────────────────────────────────┐
│ [ A ]        [ J ]      [ B ][ C ]
├─────────────────────────────────┤
│ [ S ]   скрытое поле рилсов      │
├─────────────────────────────────┤
│                                 │
│              V                  │
│            ЭКРАН                │
│                                 │
├─────────────────────────────────┤
│ [ D ]   [ X ]   [ F ]   [ Z ]   [ Y ]
└─────────────────────────────────┘
```

## Верхняя зона

- **A** — Назад.
- **J** — Заголовок текущего экрана.
- **B** — Главное действие текущего экрана.
- **C** — Вторичное действие / настройки. Если реального действия нет, слот не заполняется искусственно.

## Рабочая область

- **S** — скрытое поле рилсов. Показывается только там, где оно действительно нужно.
- **V** — основной экран / содержимое текущего раздела.

## Нижнее меню

- **D** — Главная.
- **X** — График.
- **F** — Журнал.
- **Z** — Чат.
- **Y** — Настройки.

## Правила

1. Новые и перерабатываемые разделы Book строятся сразу на этом shell.
2. Не создавать дополнительные локальные шапки и дублирующие кнопки поверх A/J/B/C.
3. Основное действие экрана размещается в B, если оно есть.
4. C используется только при наличии реального вторичного действия.
5. Контент раздела живёт внутри V.
6. S остаётся скрытым, если текущему экрану поле рилсов не требуется.
7. Нижнее меню D/X/F/Z/Y относится к общему Book shell и не рисуется заново внутри отдельных разделов.
8. Модальные окна — отдельный слой и не обязаны повторять A/J/B/C.

## Назначение документа

При обсуждении архитектуры можно использовать буквенные коды напрямую: например, «B = Сохранить», «S скрыто», «в V три папки». Это считается однозначной ссылкой на данный стандарт.
