# Book Shell — буквенная схема интерфейса

Этот документ фиксирует общий стандарт Book shell для всех новых и постепенно перерабатываемых разделов Book. Это не клиентский shell: мастер и клиент используют один размер и общие компоненты Book.

## Схема

```text
┌─────────────────────────────────┐
│ [ A ]        [ J ]      [ B ][ C ]
├─────────────────────────────────┤
│ [ S ]   скрытая горизонтальная зона │
├─────────────────────────────────┤
│                                 │
│              V                  │
│            ЭКРАН                │
│                                 │
├─────────────────────────────────┤
│ [ D ]   [ X ]   [ F ]   [ Z ]   [ Y ]
└─────────────────────────────────┘
```

## Размер

- Единый максимальный размер приложения Book: **390 px**.
- Профиль мастера и профиль клиента наследуют один и тот же `--app-max-width`.
- Локальные разделы не задают собственную ширину приложения.

## Верхняя зона

- **A** — Назад.
- **J** — Заголовок текущего экрана.
- **B** — Главное действие текущего экрана. Если действие зависит от изменений, кнопка появляется только после изменения данных.
- **C** — Вторичное действие / настройки. Если реального действия нет, слот не должен занимать полезное место.
- A/J/B/C перераспределяют свободное пространство только между фактически присутствующими элементами; пустой слот имеет нулевую ширину.
- Название J не обрезается многоточием: сначала используется доступное пространство и адаптивный размер шрифта, затем допускается перенос.
- Название действия B не обрезается многоточием. Эталон проверяет типовые подписи `Сохранить`, `Далее`, `Готово`, `Добавить`, `Создать`.

## Рабочая область

- **S** — скрываемая горизонтальная зона. Здесь могут жить рилсы, переключатели, категории или быстрые фильтры. Если элементов больше ширины телефона, горизонтальная прокрутка разрешена внутри S. Если S не нужен, он полностью исчезает.
- **V** — основной экран / содержимое текущего раздела. Сам V не должен уезжать за ширину телефона и не получает горизонтальную прокрутку.
- Для одиночной профильной карточки: если S отсутствует, карточка центрируется в свободной области V; если S присутствует, контент начинается под S.

## Нижнее меню

- **D** — Главная.
- **X** — График.
- **F** — Журнал.
- **Z** — Чат.
- **Y** — Настройки.
- Нижняя навигация всегда делит доступную ширину на **5 равных мест**.
- Все пять подписей полностью помещаются внутри своего места и имеют одинаковую типографику.

## Визуальный эталон

Официальный технический стенд находится в `ui/reference/`.

Эталон — это **UI без бизнес-логики**:
- не обращается к API;
- не читает и не записывает бизнес-данные;
- не использует серверную логику, `localStorage` или `sessionStorage`;
- использует только условные демонстрационные значения;
- собирается из тех же настоящих общих UI-компонентов, что и рабочий Book.

Техническая панель управления эталоном расположена **снаружи 390 px телефона** и не является частью интерфейса Book.

Через стенд можно переключать:
- профильную карточку без S;
- профильную карточку с S;
- чат;
- форму;
- список;
- пустое состояние;
- варианты A/J/B/C;
- короткий и длинный J;
- подписи B `Сохранить / Далее / Готово / Добавить / Создать`;
- чат со скрепкой и без скрепки.

C в эталоне открывает настоящее общее модальное окно. В нём показывается утверждённый порядок настроек профиля. Оттуда можно открыть эталонные формы `Личные данные`, `Согласия`, `Изменить пароль` и оценивать размеры общих полей, Select и других UI-элементов без сохранения данных.

## Правила

1. Новые и перерабатываемые разделы Book строятся сразу на этом shell.
2. Не создавать дополнительные локальные шапки и дублирующие кнопки поверх A/J/B/C.
3. Основное действие экрана размещается в B, если оно есть.
4. C используется только при наличии реального вторичного действия.
5. Контент раздела живёт внутри V.
6. S остаётся скрытым, если текущему экрану горизонтальная зона не требуется.
7. Нижнее меню D/X/F/Z/Y относится к общему Book shell и не рисуется заново внутри отдельных разделов.
8. Модальные окна — отдельный слой и не обязаны повторять A/J/B/C.
9. Папки/разделы в модале отображаются обычным листом строк, а не набором кнопок.
10. Действия отображаются кнопками. Название действия на кнопке центрируется. Если равнозначных действий больше одного, используются белые кнопки с коричневым контуром; несколько бежевых кнопок подряд не используются.
11. Интерфейс проектируется mobile-first: минимальная рабочая ширина 320 px, максимальная ширина Book 390 px, элементы управления не должны выходить за экран.
12. Если экран должен выглядеть «как эталон», он обязан использовать те же общие компоненты, а не копировать их локальными стилями.
13. Эталон не содержит бизнес-правил: он проверяет только форму экрана, состояния shell и UI-компоненты.

## Настройки профиля — эталон действий

Настройки профиля показываются в модальном окне, открываемом из C:

1. `Личные данные` — белая кнопка с коричневым контуром.
2. `Согласия` — белая кнопка с коричневым контуром.
3. `Изменить пароль` — коричневая основная кнопка.
4. `Выход` — существующий destructive-дизайн без изменения.

## Назначение документа

При обсуждении архитектуры можно использовать буквенные коды напрямую: например, «B = Сохранить», «S скрыто», «в V только ссылки». Фраза «как эталон Book» означает использование компонентов и правил из `ui/reference/` и этого документа без локальной перерисовки.
