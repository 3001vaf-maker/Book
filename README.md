# Book

Mobile-first application foundation. Book развивается последовательно: каждое новое ТЗ продолжает существующее приложение и не переписывает уже реализованное, если это прямо не указано в новом ТЗ.

## Навигация по документации

### Общая архитектура

`/ARCHITECTURE_DICTIONARY.md`

Общий архитектурный словарь проекта находится **в корне репозитория**. Это единый источник общих архитектурных правил.

В папке `/ТЗ` второй `ARCHITECTURE_DICTIONARY.md` не создаётся.

### Технические задания

`/ТЗ/`

Все документы ТЗ находятся в этой папке.

### Реестр ТЗ

`/ТЗ/тз.md`

Здесь находится последовательность ТЗ и их назначение. Следующий номер ТЗ определяется по этому реестру.

### Реестр сущностей

`/ТЗ/сущностей.md`

Здесь находится реестр сущностей и присвоенные им E-коды. Новый E-код определяется по этому реестру.

### Отдельные ТЗ

`/ТЗ/ТЗ-*.md`

Здесь находятся отдельные документы конкретных ТЗ.

Старые ТЗ не переписываются задним числом. Если существующая реализация или название изменяется последующим ТЗ, изменение фиксируется последующим ТЗ, сохраняя историю предыдущего состояния.

## Порядок работы с ТЗ

Перед созданием или реализацией нового ТЗ необходимо:

1. Проверить `/ТЗ/тз.md`.
2. Проверить `/ТЗ/сущностей.md`.
3. Проверить соответствующее существующее ТЗ, если оно уже относится к данной ветке.
4. Проверить текущую реализацию приложения и существующую ветку.
5. При необходимости свериться с `/ARCHITECTURE_DICTIONARY.md`.

Не создавать новые реестры, дублирующие документы или параллельные архитектурные ветки без необходимости.

Если обнаружено расхождение между новым требованием и существующей документацией или реализацией, сначала определить и зафиксировать характер расхождения, а не самостоятельно переписывать историю проекта.
