# Book — словарь дизайна

Этот документ — единый словарь утверждённых визуальных решений Book. В качестве исходной визуальной базы используются уже существующие решения CoBook; CSS-код CoBook не переносится.

## 1. ЕДИНЫЙ ИСТОЧНИК CSS

В Book используется один общий источник CSS: `styles.css`.

Функциональные папки не создают собственные CSS-файлы. Визуальные правила не исправляются локальными костылями внутри отдельных папок.

## 5. ПАПКА

`FOLDER` — единый UI-компонент.

Базовые признаки:

- ширина `100%`;
- граница `--mocha-border`;
- радиус `16px`;
- фон `--ui-folder`;
- единый вертикальный шаг `12px`;
- содержимое может включать иконку, название, дополнительный текст и стрелку.

`FEATURE FOLDER` — только крупный визуальный вариант `FOLDER`. Это не кнопка и не отдельная CSS-система.

## 6. КНОПКА

`BUTTON` — именно кнопка действия.

Основной вариант использует `--ui-action` и белый текст. Вторичный — `--ui-secondary` и границу. Опасный — `--ui-danger` и `--ui-danger-bg`.

Папка не называется кнопкой только потому, что по ней можно нажать.

## 7. СПИСКИ И КАРТОЧКИ

`LIST` — единая визуальная система перечней. `LIST ITEM` использует общую геометрию, типографику, границы и состояния.

`CARD` — единый UI-компонент с общей поверхностью, границей, радиусом, отступами, типографикой и состояниями.

Функциональные данные не создают отдельные CSS-системы.

## 8. ПОЛЯ И ФОРМЫ

Базовое поле:

- минимальная высота `48px`;
- внутренний отступ `12px`;
- граница `--mocha-border`;
- радиус `12px`;
- фон `--ui-bg`;
- текст `--mocha-dark`.

`TEXTAREA` имеет минимальную высоту `96px`. Подписи — обычно `12px` и `--mocha-medium`.

## 9. НАВИГАЦИЯ

`BOTTOM NAVIGATION` — одна реализация на всё приложение:

- фиксирована снизу;
- пять равных пунктов;
- неактивное состояние — `--mocha-medium`;
- активное — `--mocha-dark`;
- подпись `11px`;
- иконка около `18px`;
- промежуток между иконкой и подписью около `3px`.

## 10. BACK — НАЗАД

Единый внешний вид:

- высота `48px`;
- фон `--ui-back`;
- граница `--mocha-border`;
- текст `--mocha-dark`;
- радиус `14px`.

Внешний вид и место кнопки едины во всём приложении. Поведение задаётся архитектурным словарём: **ровно один шаг назад**.

## 11. MODAL И BOTTOM SHEET

`MODAL` и `BOTTOM SHEET` — разные UI-компоненты.

Они используют общий overlay-механизм. `BOTTOM SHEET` имеет единое крупное скругление верхних углов и учитывает безопасную область устройства.

## 12. КАЛЕНДАРЬ

Общий визуальный каркас календаря:

- сетка `7` колонок;
- дни недели `12px`, жирное начертание;
- обычная ячейка месяца — минимум `44px` по высоте;
- календарь Графика использует строку около `48px`;
- календарная ячейка — около `40px` по высоте;
- радиус ячейки `10px`;
- выбранный день — `--ui-action` + белый текст;
- рабочий день — `--cashmere`;
- выходные — `#b84a4a`;
- внешние дни — `--mocha-light`.

Календари разных функциональных папок могут иметь разное поведение, но общий визуальный каркас один.

## 13. ПЕРЕКЛЮЧАТЕЛИ / ВКЛАДКИ

Общий визуальный принцип:

- высота около `46px`;
- граница `--mocha-border`;
- радиус около `13px`;
- неактивный фон `--ui-bg`;
- активный фон `--ui-tab-active`;
- активный текст `--mocha-dark`;
- неактивный текст `--mocha-medium`.

## 14. ПУСТОЕ СОСТОЯНИЕ

Типовое пустое состояние:

- мягкий фон `--cashmere`;
- пунктирная граница `--mocha-border`;
- крупный внутренний отступ;
- центрированное содержимое;
- заголовок;
- поясняющий текст.

## 15. СОСТОЯНИЯ UI

| Состояние | Правило |
|---|---|
| Active | `--ui-action` или `--ui-tab-active` в зависимости от компонента |
| Disabled | приглушённый цвет |
| Focus | мягкая контурная обводка |
| Error / Danger | `--ui-danger` + `--ui-danger-bg` |
| Loading | единое состояние загрузки компонента |
| Empty | единое пустое состояние |

## 16. ФОРМА ПРИЛОЖЕНИЯ — СМАРТФОН

**Основная форма Book — смартфон.** Это единый адаптивный UI для iPhone, Android, Huawei и других смартфонов, а не отдельные версии интерфейса.

Правила:

- интерфейс всегда помещается в ширину экрана;
- горизонтального переполнения быть не должно;
- длинный текст переносится;
- элементы используют доступную ширину;
- поля и кнопки не выходят за границы экрана;
- изображения, SVG и другие медиа не расширяют страницу;
- календарная сетка всегда остаётся внутри доступной ширины;
- нижняя навигация учитывает `safe-area` устройства;
- узкие экраны могут уменьшать внешние отступы и подписи навигации, но не получают отдельные UI-компоненты;
- минимальная рабочая ширина интерфейса — `320px`.

## 17. DESKTOP / MAC

Mac и другие большие экраны являются адаптивным режимом того же приложения.

Допускается ограниченная ширина оболочки для сохранения формы приложения. Внутренняя структура UI не меняется.

Отдельные desktop-компоненты не создаются.

## 18. ТЕНЬ

Базовая мягкая тень списков:

`0 1px 6px rgba(59,48,43,.018)`

Тяжёлые тени не вводятся без отдельного решения.

## 19. ЕДИНЫЙ ИСТОЧНИК

Один визуальный компонент — одна реализация.

Функциональные папки получают доступ к общему UI и не создают копии папок, кнопок, списков, карточек, модальных окон или мобильных оболочек.

Изменение общего дизайна выполняется через единую UI/CSS-систему.

## 20. ЧЕГО НЕ ДЕЛАЕМ

- не копируем CSS из CoBook;
- не создаём `mobile.css`;
- не создаём CSS внутри функциональных папок;
- не создаём отдельные mobile/desktop-компоненты;
- не исправляем общий UI локальным костылём;
- не вводим новые цвета или шрифты только для одного экрана.

Если в CoBook обнаруживается визуальное решение, которое не было утверждено или противоречит правилам, оно не становится автоматически правилом Book.
