# Book — словарь дизайна

Источник: визуальные решения, уже существующие в CoBook. Этот документ фиксирует их как требования для нового Book. CSS-код CoBook не переносится.

## 1. Назначение

`DESIGN_DICTIONARY.md` — словарь утверждённых визуальных решений.

Он отвечает на вопрос:

> **Как должен выглядеть Book, чтобы уже утверждённые решения CoBook не пришлось придумывать заново?**

Это не CSS и не инструкция копировать `styles.css` из CoBook.

---

## 2. ЕДИНЫЙ ИСТОЧНИК CSS

В Book должен быть один общий источник CSS:

```text
styles.css
```

Функциональные папки не получают собственные CSS-файлы.

```text
journal.css      ❌
service.css      ❌
profile.css      ❌
loyalty.css      ❌
```

Владелец папки отвечает за данные и поведение. Общий UI и визуальные правила принадлежат единой CSS/UI-системе.

Это соответствует визуальному правилу CoBook: один `styles.css`, а функциональные папки не владеют отдельным CSS. fileciteturn120file0

## 7. ПАПКА

Визуальная папка — единый UI-компонент.

Базовые признаки существующей папки CoBook:

- ширина — `100%`;
- граница — `--mocha-border`;
- радиус — `--ui-folder-radius`;
- фон — `--ui-folder`;
- мягкая тень — `--ui-list-shadow`;
- стандартный вертикальный шаг — `--ui-gap`;
- содержимое может включать иконку, название, дополнительный текст и стрелку.

`FEATURE FOLDER` не является отдельной системой дизайна. Это крупный визуальный вариант папки. В архитектуре Book он должен оставаться вариантом `FOLDER`, а не превращаться в `FEATURE BUTTON`.

## 8. КНОПКА

Кнопка — именно **кнопка**, не папка.

Визуальная система предусматривает варианты:

```text
BUTTON
├── основной
├── вторичный
├── действие
├── опасное действие
└── специальный вариант
```

Основная кнопка использует тёмный `--ui-action` и белый текст. Вторичная — мягкую поверхность `--ui-secondary` и границу. Опасная — `--ui-danger` и `--ui-danger-bg`.

В CoBook эти варианты являются частью общей CSS-системы. fileciteturn120file0

## 9. СПИСКИ

`LIST` — единая визуальная система перечней.

Разные функциональные списки могут иметь разные данные и действия, но общая геометрия должна оставаться общей:

```text
LIST
├── общая геометрия
├── общие отступы
├── общая типографика
├── общие границы
├── общие состояния
└── варианты
```

В CoBook один и тот же визуальный принцип используется для Прайса, Товаров, Лояльности, Клиентов и других списков. fileciteturn91file0

## 13. НАЗАД

Кнопка `BACK` имеет единый визуальный язык:

- высота `48px`;
- фон `--ui-back`;
- граница `--mocha-border`;
- текст `--mocha-dark`;
- радиус `--ui-radius`;
- стандартный отступ от соседнего элемента — `--ui-gap`.

В CoBook часть экранов использует фиксированное положение кнопки «Назад» над нижней навигацией. Это существующее решение фиксируется как визуальный эталон, но в Book его реализация должна быть единой, а не размноженной по папкам.

Архитектурное правило Book: `BACK` возвращает ровно на один предыдущий уровень.

Общее:

Для нижней панели в CoBook используется крупное скругление верхних углов `20px`, светлая поверхность и ограничение ширины до `520px` на соответствующих листах. fileciteturn100file0

`BOTTOM SHEET` — это не «ещё одна кнопка» и не обычная модальная кнопка. Это панель, выезжающая снизу.

Поведение календарей Журнала и Графика остаётся раздельным; общим является визуальный каркас. Это прямо закреплено в UI-реестре CoBook. fileciteturn92file0 fileciteturn102file0

## 18. СТАНДАРТНЫЕ СОСТОЯНИЯ

Используются единые визуальные принципы:

| Состояние | Визуальный принцип |
|---|---|
| Обычное | базовый фон и текст |
| Активное | `--ui-action` или `--ui-tab-active` в зависимости от компонента |
| Нажатие | снижение визуальной интенсивности / `opacity` |
| Опасное | `--ui-danger` + `--ui-danger-bg` |
| Неактивное | приглушённый цвет |
| Фокус | мягкая контурная обводка |

## 19. МОБИЛЬНАЯ ГЕОМЕТРИЯ

CoBook уже содержит отдельные мобильные правила. Основное зафиксированное правило:

- до `560px` горизонтальный padding контента уменьшается до `14px`;
- нижняя навигация остаётся полной ширины доступной оболочки;
- сетки и панели адаптируются без создания отдельного мобильного CSS-файла;
- компоненты сохраняют общий визуальный язык.

В Book мобильная версия не должна быть отдельной дизайн-системой.

## 22. ЧТО МЫ НЕ ПЕРЕНОСИМ КАК ПРАВИЛО

Этот документ **не означает**, что весь CSS CoBook считается идеальным.

Из CoBook переносится:

```text
УТВЕРЖДЁННОЕ ВИЗУАЛЬНОЕ РЕШЕНИЕ
        ↓
фиксируется здесь
        ↓
реализуется новым чистым CSS в Book
```

Не переносится автоматически:

```text
старый CSS-код ❌
старые дубли ❌
ошибочная архитектура ❌
непонятные зависимости ❌
случайные локальные исправления ❌
```

Если в CoBook обнаруживается визуальное решение, которое не было утверждено или явно противоречит правилам, оно не становится автоматически правилом Book.

## 23. ГЛАВНОЕ ПРАВИЛО BOOK

```text
CoBook
  ↓
существующие утверждённые визуальные решения
  ↓
DESIGN_DICTIONARY.md
  ↓
новый чистый UI Book
  ↓
один styles.css
```

**Дизайн не придумываем заново. Код не копируем.**

Архитектурный словарь определяет, **кто за что отвечает**. Этот словарь определяет, **как утверждённый интерфейс должен выглядеть**.
