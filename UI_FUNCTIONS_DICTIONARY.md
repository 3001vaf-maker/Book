# Book — реестр UI-функций

## Назначение

Этот документ является живым реестром всех общих UI-функций проекта Book.

Его задача — позволять быстро определить:

- что делает UI-функция;
- где находится её единственная реализация;
- к какой категории UI она относится;
- где она используется;
- с какими сущностями или функциями работает;
- является ли она общей, специализированной или временной;
- есть ли похожие функции или папки, которые могут оказаться дубликатами.

**Главное правило:** перед созданием новой UI-функции сначала проверяется этот реестр. Если подходящая функция уже существует — используется она, а не создаётся новая копия.

---

## 1. Главные правила

### 1.1. Одна функция — одна реализация

Одна общая UI-функция имеет:

- одно имя;
- одну реализацию;
- одно каноническое место хранения;
- записи о назначении и использовании в этом реестре.

Копирование одной UI-функции в разные папки запрещено.

### 1.2. `ui/ui.js` — только фасад

`ui/ui.js` является публичным фасадом UI-системы.

Он может:

- импортировать функции из UI-папок;
- реэкспортировать функции;
- содержать только действительно локальную реализацию, если для неё ещё невозможно определить отдельную общую категорию.

`ui/ui.js` не должен превращаться в место хранения всех реализаций.

### 1.3. Новая функция регистрируется сразу

При добавлении новой UI-функции одновременно обновляется этот документ.

Для каждой функции обязательно указывается:

- русское понятное описание;
- имя функции;
- путь реализации;
- тип;
- место использования;
- с чем она работает;
- статус.

Изменение UI-функции без обновления реестра не считается завершённым изменением архитектуры UI.

### 1.4. Если категория пока не определена

Не нужно создавать отдельную постоянную папку только ради одной функции.

Если функция действительно локальная и категория пока не определена, она может временно оставаться отдельно с явной отметкой в реестре:

`ВРЕМЕННАЯ / КАНДИДАТ НА ГРУППИРОВКУ`

После появления нескольких функций одного типа определяется общая категория и создаётся каноническая папка.

### 1.5. Если появились похожие папки

Перед созданием второй похожей папки необходимо проверить этот реестр.

Если функции относятся к одной UI-категории и не имеют принципиального различия по назначению, выбирается одна каноническая папка, а дубликат устраняется.

Если различие принципиальное, оно должно быть явно записано в реестре.

## 5. Разница между похожими функциями

### `timePicker()` и `durationPicker()` — не считать дубликатами

Они могут иметь похожее визуальное поведение, но работают с разными данными:

- `timePicker()` — **момент времени**, например `10:00`;
- `durationPicker()` — **продолжительность**, например `1 ч 30 мин`.

Визуальное объединение в будущем возможно, если будет создан общий механизм, но модели данных и назначения должны оставаться различимыми.

### `timePicker()` и `timeInput()` — не две реализации

`timePicker()` является канонической реализацией UI выбора времени в `ui/time/`.

`timeInput()` в `ui/ui.js` является фасадным вызовом этой реализации и не должен развиваться в отдельный компонент.

Конфигурация `minuteStep` позволяет использовать один и тот же time picker для разных режимов времени без создания отдельных компонентов.

### `timePicker()` и единый барабан

Барабан выбора — один общий UI-механизм внутри `ui/time/`. Разными являются только данные, передаваемые ему:

- часы `00–23` + минуты `00, 15, 30, 45` — выбор времени с шагом 15 минут;
- часы `00–23` + минуты `00–59` — выбор времени с шагом 1 минута;
- часы `1–12` + минуты `1–59` — выбор длительности.

Не создавать `TimeWheel15`, `TimeWheel1` или `DurationWheel` как отдельные UI-компоненты.

### `costField()` — специализированный компонент

Внутренний переключатель вариантов стоимости (`Стоимость / от / от–до`) является частью компонента стоимости. Сам по себе он пока не считается отдельным общим `tabs` или `segment-control`.

Не создавать отдельную общую функцию только на основании этого внутреннего механизма, пока она реально не потребуется в другом месте.

### `list()` и `listEntry()` — не считать дубликатами

`list()` — канонический Core UI List для простого перечня значений. Он не знает сущностей и не рисует карточки. Заголовок элемента является основным значением; все остальные запрошенные значения являются второстепенными и отображаются светлее и тоньше.

`listEntry()` — существующий компонент записи внутри специализированных/entity-листов. Он сохраняется отдельно и не должен использоваться как подмена Core UI List.

Для `list()` не создаются отдельные CSS-правила под Клиентов, Процедуры, Журнал или другие сущности.

## 7. Правило переноса функции

Если функция временно находится в `ui/ui.js`, но становится понятна её постоянная категория:

1. определить каноническую папку;
2. перенести туда реализацию;
3. оставить в `ui/ui.js` только импорт и реэкспорт;
4. обновить путь в этом реестре;
5. проверить всех потребителей функции;
6. сделать перенос отдельным понятным изменением.

Перенос не должен менять поведение функции без отдельного требования.

---

## 8. Правило объединения папок

Если появляются две папки с похожими функциями:

1. сравнить назначение функций;
2. сравнить модели данных;
3. проверить реальные места использования;
4. определить, действительно ли это разные UI-компоненты;
5. если нет — выбрать одну каноническую папку;
6. перенести функции;
7. удалить дубликат;
8. обновить этот реестр.

**Запрещено создавать две UI-системы только из-за похожего внешнего вида.**

## 9. Что означает статус

| Статус | Значение |
|---|---|
| `ОБЩАЯ` | Компонент используется в разных местах приложения. |
| `КАНОНИЧЕСКАЯ` | Утверждён единый компонент для данной задачи. |
| `СПЕЦИАЛИЗИРОВАННАЯ` | Компонент предназначен для конкретного типа UI/данных, но может использоваться несколькими сущностями. |
| `ОБЩАЯ УТИЛИТА` | Низкоуровневая функция, не являющаяся самостоятельным визуальным компонентом. |
| `ВРЕМЕННАЯ / КАНДИДАТ НА ГРУППИРОВКУ` | Функция пока не имеет определённой общей категории. |
| `ТРЕБУЕТ РЕШЕНИЯ О ПЕРЕНОСЕ` | Функция уже общая, но её реализация пока находится не в оптимальном каноническом месте. |
| `НЕ ПОДКЛЮЧЕНА К ФАСАДУ` | Функция существует в своей папке, но пока не экспортируется через `ui/ui.js`. Это не означает, что её нужно автоматически подключать. |

## 10. Обязательное правило для будущих чатов

Любой следующий чат, который изменяет UI Book, должен сначала ориентироваться по этому реестру.

Перед созданием новой функции необходимо ответить на вопросы:

1. Есть ли уже такая функция?
2. Если есть — почему нельзя использовать её?
3. Если нужна новая — чем она отличается?
4. К какой UI-категории она относится?
5. В какой папке должна находиться её единственная реализация?
6. Где она используется?
7. Нужно ли добавить её в `ui/ui.js` как публичный экспорт?
8. Обновлён ли этот реестр в том же изменении?
